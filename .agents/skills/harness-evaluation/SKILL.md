# Harness evaluation

Define the expected observable result and unacceptable outcomes before the run. Separate structural checks, unit tests, live model behavior, visual inspection, and clean-machine installation; one passing layer does not prove the others.

Exercise the happy path plus missing model, busy lock, context overflow, malformed tool result, timeout, and interrupted download where relevant. Record versions, inputs, receipts, failures, and uncertainty. Do not describe one successful stochastic run as general reliability or let the agent's own completion claim replace external evidence.
